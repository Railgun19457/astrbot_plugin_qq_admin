# QQ群管

基于 **OneBot v11（aiocqhttp）** 的 QQ 群管理插件，支持**指令**与 **LLM 工具**两种调用方式。

> 仅支持 aiocqhttp 协议端。其他平台上插件完全静默，不会出现「指令触发了但底层没有接口可用」的情况。

## 功能

| 功能 | 说明 |
| --- | --- |
| 禁言 / 解禁 | 支持 `@` 目标、回复式目标、手打 QQ 号；时长支持 `10m` `2h` `1d` |
| 全群禁言 | 作为「禁言」的参数使用，带时长时自动解除 |
| 踢人 | 支持可选理由 |
| 撤回消息 | 回复目标消息后使用 |
| 群公告 | 发送与查看 |
| 黑名单 | 永久或临时拉黑，**拉黑原因会记录并出现在导出表格中** |
| 多群分组 | 多个群组成一组，组内共享黑名单与通知会话 |
| 进群审核 | 关键词放行、黑名单拒绝、等级校验、转人工确认 |
| 导出表格 | 群成员名单与拉黑名单导出为 xlsx 并上传到群文件 |
| 审计日志 | 所有管理操作留痕，可追溯操作人 |
| LLM 工具 | 以上能力可按需开放给大模型调用（默认全部关闭） |

## 安装

在 WebUI 的插件市场搜索「QQ群管」安装，或手动放入 `data/plugins/`。

依赖 `openpyxl`，安装插件时会自动处理。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/禁言 @某人 [时长] [理由]` | 时长支持 `10m` `2h` `1d`，省略则用默认值 |
| `/禁言 全体 [时长]` | 全群禁言，**高危操作需要确认** |
| `/解禁 @某人` / `/解禁 全体` | 解除禁言 |
| `/踢 @某人 [理由]` | 移出本群，**高危操作需要确认** |
| `/撤回` | 回复目标消息后使用 |
| `/群公告 [内容]` | 不带内容则查看当前公告 |
| `/拉黑 @某人 [原因] [时长]` | 加入本群组共享黑名单 |
| `/解除拉黑 @某人` | 移出黑名单 |
| `/黑名单` | 查看本群组黑名单及拉黑原因 |
| `/群成员 [页码]` | 群成员概览 |
| `/群导出 成员` / `/群导出 黑名单` | 生成 xlsx 并上传到群文件 |
| `/审核` | 查看待审核的进群申请 |
| `/审核同意 <编号>` / `/审核拒绝 <编号>` | 处理指定申请 |
| `/群管` | 查看指令帮助 |
| `/群管状态` | 插件运行状态与群组归属 |

参数位置无关：`/禁言 @某人 10m 刷屏`、`/禁言 @某人 刷屏`、`/禁言 @某人 10m` 都能正确解析。

## 权限

以下三种身份**任一命中**即可使用管理指令：

1. **AstrBot 全局管理员**（`admins_id` 或插件配置里的自定义白名单）
2. **群主 / 群管理员**（按 OneBot 的 `role` 字段判定）
3. **普通成员**（仅限查询类指令，可在配置中关闭）

每种能力的所需等级可在配置中单独调整，例如把「导出表格」放宽到群管理员，或把「查询」收紧到仅管理员。

## 配置要点

- **群组定义**：在配置里添加群组，填入群号列表；同组的群共享黑名单。可选的「管理会话」用于接收进群审核通知，格式 `group:123456`（群聊）或 `private:10001`（私聊），留空则回退到申请所在的群；「开启审核通知」关闭后该群组不再推送任何审核通知
- **进群审核**：默认关闭。开启后可配置关键词规则、黑名单拒绝、最低 QQ 等级、是否转人工确认，以及无人值守时的兜底行为（默认保持待审）
- **LLM 工具**：默认**一个都不开启**

## 注意事项

- **指令名冲突**：AstrBot 允许不同插件存在同名指令，重名时**会同时触发多个插件**。本插件刻意使用较具体的名字（如 `/群公告` 而非 `/公告`）降低撞名概率。若确实冲突，请在 WebUI 的 **插件 → 管理行为** 中重命名或添加别名，无需改动插件配置。
- **`@` 前需要空格**：框架要求指令后跟空格，所以 `/禁言@某人` 不会被识别，请写成 `/禁言 @某人`。
- **协议端差异**：群公告（`_send_group_notice`）与 QQ 等级（`_get_group_member_info` 的 `level`）都是协议端私有扩展，并非所有实现都提供。不支持时会给出明确提示或跳过该项校验，建议使用 NapCat 或 Lagrange。
- **全群禁言的定时**：OneBot 的全群禁言是纯开关，服务端不会自动解除。带时长时由插件记录到期时间并定时解除；该时间会**持久化到 `whole_ban.json`**，因此插件重启后会自动恢复定时（恢复前会先向协议端确认该群是否仍处于禁言状态，避免误解除）。只有协议端不可用时才会保留记录等下次启动重试。
- **LLM 工具的风险**：AstrBot 对非内置工具的权限门控默认不拦截，也就是说只要把工具暴露给模型，能跟机器人对话的人就可能通过自然语言命令它禁言或踢人。本插件已在每个工具内部重新校验权限，并按「群号不作为参数」的方式防止跨群操作，但仍建议：**只在你信任对话人群的场景下开启**，并可在 WebUI 的「扩展 → 组件」里把这些工具额外设为 admin 级。

## 数据文件

全部位于 `data/plugin_data/astrbot_plugin_qq_admin/`，更新或重装插件不会丢失：

| 文件 | 内容 |
| --- | --- |
| `blacklist.json` | 各群组的黑名单 |
| `audit.jsonl` | 审计日志，一行一条 |
| `pending_reviews.json` | 待人工处理的进群申请 |
| `whole_ban.json` | 全群禁言的到期时间，重启后据此恢复定时 |
| `exports/` | 导出的临时表格，按配置自动清理 |
