# QQ 群管

![:name](https://count.getloli.com/@astrbot_plugin_qq_admin?name=astrbot_plugin_qq_admin&theme=miku&padding=7&offset=0&align=top&scale=1&pixelated=1&darkmode=auto)

基于 **OneBot v11（aiocqhttp）** 的 QQ 群管理插件，支持指令和 LLM 工具调用。

> 仅支持 `aiocqhttp` 协议端（如 NapCat、Lagrange）。其他平台不会响应。

## 功能

- 禁言 / 解禁 / 全群禁言（可定时自动解除）、踢人、撤回
- 黑名单：群组内共享、永久有效，记录拉黑所在群，可自动撤回其发言、拉黑后踢出
- 多群分组：每个群组独立配置默认禁言时长、黑名单与进群审核，组内共享黑名单
- 进群审核：关键词、黑名单、QQ 等级、跨群免审核；需人工确认时引用通知回复同意/拒绝即可
- 管理会话：群管理员的控制台，指令与群内一致，集中接收审核通知与处理申请
- 导出群成员与黑名单为 xlsx 并上传到群文件
- 审计日志
- 可按需向 LLM 开放管理工具（默认关闭）

## 安装

在 AstrBot WebUI 的插件市场搜索「QQ群管」安装，或将插件放入 `data/plugins/`。依赖 `openpyxl`，安装时自动处理。

## 指令

> 下表用 `/` 作为指令前缀；实际前缀跟随 AstrBot 的唤醒前缀（默认 `/`）。也可以 @ 机器人或引用机器人消息后直接发指令名。

| 指令 | 说明 |
| --- | --- |
| `/禁言 @用户 [时长]` | 时长支持 `600`、`10m`、`2h`、`1d`；省略时用群组默认时长 |
| `/禁言 全体 [时长]` | 全群禁言，带时长会到时自动解除 |
| `/解禁 @用户` / `/解禁 全体` | 解除禁言 |
| `/踢 @用户` | 移出群聊（默认需要二次确认） |
| `/撤回` | 引用目标消息后发送本指令 |
| `/拉黑 @用户 [原因]` | 永久加入黑名单，原因会记入导出表格 |
| `/解除拉黑 @用户` | 移出黑名单 |
| `/黑名单` | 查看当前会话可见的黑名单（含拉黑所在群） |
| `/导出 成员` / `/导出 黑名单` | 导出 xlsx 并上传到群文件 |
| `/群管状态` | 运行状态、群组归属与通知路由 |
| `/群管` | 查看帮助 |

**目标写法**：`@某人`、引用对方消息、直接填写 QQ 号三种形式等价，可混用。时长与目标的位置可以互换。

**两个会话都能用**：在群里执行时目标群就是当前群；在管理会话里执行时用 `#群号` 指明目标群，例如 `/禁言 #123456 @某人 10m`（`#群号` 写在指令名之后；该管理会话只对应一个群时可省略）。`/黑名单`、`/导出`、`/拉黑`、`/解除拉黑` 无需指定群号——它们作用于当前会话能看到的全部群组。

**进群申请的人工确认**：通知里会提示处理方式——引用该通知回复「同意」或「拒绝」（也接受配置里的确认词 / 取消词）。通知与申请绑定并持久化，重启后仍可引用；仅有一条待处理申请时也可不引用直接回复。

**群公告**只通过 LLM 工具操作（需在「函数工具选项」里开启）：`qq_send_group_notice` 发送（可带配图）、`qq_group_notice_query` 查看公告及其编号、`qq_group_notice_delete` 按编号删除。三者都依赖协议端扩展，不支持时会明确提示。

## 权限

指令默认允许 AstrBot 全局管理员、插件白名单、管理会话所在群的用户、群主与群管理员使用；查询类指令默认也允许普通成员。每项能力（禁言 / 全群禁言 / 踢人 / 撤回 / 黑名单 / 查询 / 进群审核 / 导出）都可以在配置里单独设为「任何人」「群管理员」或「AstrBot 管理员」。

## 配置要点

插件只对「群组定义」里配置的群生效，未列入的群不响应任何指令、自动审核与黑名单拦截。

- **群组定义**：填写群号列表，同一群组内的群共享黑名单。**同时接入多个 QQ 时**，群号对所有实例生效；若只让其中一个 QQ 执行管理，把该项写成该群的会话 UMO（如 `aiocqhttp:GroupMessage:123456`，在目标群发 `/sid` 获取），这样只有那个实例的消息会被管理。
- **管理会话**：群管理员控制台的会话 UMO。指令集与群内完全一致，需要落到具体群时用 `#群号`。留空则通知发回申请所在群，管理在各群内完成。
- **多 QQ（多个平台实例）**：通知目标、进群申请的 `flag`、全群禁言的定时解除都记录产生它们的平台实例，会回到同一条连接上执行；两个 QQ 可以各管各的群，也可以共用一个管理会话。
- **默认禁言时长**：每个群组单独配置，未填写时长时使用，默认 `10m`。
- **黑名单**：每个群组可单独启用或关闭并设置默认原因。拉黑**永久有效**，用 `/解除拉黑` 移出；名单记录拉黑所在群。拉黑后踢出可选 `none`（默认）/ `current`（只踢执行拉黑的群）/ `all`（踢该群组所有群，跨实例时走各自实例）。
- **进群审核**：每个群组一套通用规则 + 跨群免审核，可配置启用开关、放行关键词、黑名单拒绝、最低 QQ 等级、拒绝理由，以及未命中规则时的「默认行为」：`hold` 保持待审（安静入队）、`approve` 放行、`reject` 拒绝。
- **按群关键词 / 跨群免审核**：直接填写为整组通用；写成 `群号:关键词` 或 `目标群:来源群1,来源群2` 只对指定群生效。
- **导出**：`/导出 成员` 为每个群生成一张工作表放在同一个 xlsx 里，`/导出 黑名单` 汇总所有可见群组的条目。上传目标为当前群，或在管理会话里唯一涉及的群；无法确定时只回复本地路径。
- **通知与回执**：

  | 内容 | 触发 | 去向 |
  | --- | --- | --- |
  | `禁言`、`踢人`、`撤回`、`黑名单`、`导出` 回执 | 指令 | 固定在执行指令的会话答复；勾选后**额外**转发到管理会话（在管理会话执行时不重复发） |
  | 进群审核通知 | 申请人 | 单独选择：`origin` 申请所在群 / `manage` 管理会话（默认，未配置时回退） / `both` / `none` |

  「黑名单」回执包含 `/拉黑`、`/解除拉黑` 与拉黑后自动踢出的结果；黑名单成员发言被撤回时只记日志。审核通知涵盖新申请、自动放行 / 拒绝、保持待审提示，以及引用通知处理后的结果。LLM 工具的结果只回给模型，不产生上述通知。发送 `/黑名单 设置` 可单独查看通知路由。

- **LLM 工具**：默认全部关闭。开启前请确认对话用户可信，并建议在 WebUI「扩展 → 组件」中把工具设为 admin 级。

## 注意事项

- 未纳入配置的群不会响应任何指令，消息会交给其他插件或模型。
- 指令名与参数之间需要空格，例如 `/禁言 @用户 10m`。
- 群公告、QQ 等级、撤回等依赖协议端扩展；不支持时会提示或跳过对应校验。
- 全群禁言的定时解除由插件维护，重启后自动恢复。
- 管理操作需要协议端具备对应权限。

## 数据文件

数据保存在 `data/plugin_data/astrbot_plugin_qq_admin/`，更新或重装插件不会丢失：

- `blacklist.json`：黑名单
- `audit.jsonl`：审计日志
- `pending_reviews.json`：待处理进群申请
- `whole_ban.json`：全群禁言定时记录
- `exports/`：导出的临时表格
