# QQ 群管

![:name](https://count.getloli.com/@astrbot_plugin_qq_admin?name=astrbot_plugin_qq_admin&theme=miku&padding=7&offset=0&align=top&scale=1&pixelated=1&darkmode=auto)

基于 **OneBot v11（aiocqhttp）** 的 QQ 群管理插件，支持指令和 LLM 工具调用。

> 仅支持 `aiocqhttp` 协议端（如 NapCat、Lagrange）。其他平台不会响应。

## 功能

- 禁言、解禁、全群禁言
- 踢人、撤回消息
- 黑名单管理，可选自动撤回黑名单成员消息
- 多群分组：组内共享黑名单与审核通知，每个群组可独立配置默认禁言时长、黑名单与进群审核策略
- 管理会话：群管理员专用的会话，接收审核通知并可直接处理申请、管理群组黑名单
- 进群审核：每个群组一套通用规则，关键词和跨群免审核支持用 `群号:` 前缀精确到群；需要人工确认时引用通知回复同意/拒绝即可
- 导出群成员和黑名单为 Excel 并上传到群文件
- 审计日志
- 可按需向 LLM 开放管理工具（默认关闭，含发送群公告与群成员查询）

## 安装

在 AstrBot WebUI 的插件市场搜索「QQ群管」安装，或将插件放入 `data/plugins/`。

插件依赖 `openpyxl`，安装时会自动处理。

## 指令

> 下表用 `/` 作为指令前缀；实际前缀跟随 AstrBot 的唤醒前缀（默认 `/`），也可以 @ 机器人或引用机器人消息后直接发指令名。

| 指令 | 说明 |
| --- | --- |
| `/禁言 @用户 [时长]` | 时长支持 `600`、`10m`、`2h`、`1d`；不填用群组默认时长 |
| `/禁言 全体 [时长]` | 全群禁言，带时长会自动解除 |
| `/解禁 @用户` / `/解禁 全体` | 解除禁言 |
| `/踢 @用户` | 移出群聊（默认需要二次确认） |
| `/撤回` | 回复目标消息后撤回 |
| `/拉黑 @用户 [原因]` | 永久加入黑名单，原因会记入导出表格 |
| `/解除拉黑 @用户` | 移出黑名单 |
| `/黑名单 [群号或群组名]` | 查看黑名单及原因；在管理会话中可用参数指定群组 |
| `/导出 成员` / `/导出 黑名单` | 导出 Excel 并上传到群文件 |
| `/群管` | 查看帮助 |
| `/群管状态` | 查看插件状态和群组归属 |

**目标写法**：`@某人`、引用对方的消息、直接填写 QQ 号三种形式等价，可以混用（`禁言 123456 10m` 与 `禁言 @小王 10m` 效果相同）。

**所有指令在两个会话里都能用**：在群内使用时目标群就是当前群；在管理会话里使用时，用 `#群号` 指明目标群（`/禁言 #123456 @某人 10m`，`#群号` 写在指令名之后），如果该管理会话只对应一个群则可以省略。`@` 和引用在管理会话里同样有效——取到的都是 QQ 号。

进群申请需要人工确认时，通知里会提示处理方式：**引用该通知消息并回复「同意」或「拒绝」**（也接受配置里的确认词/取消词）。通知消息与申请绑定并会持久化，重启后仍可引用处理；会话中只有一条待处理申请时，也可以不引用直接回复。

群公告改由 LLM 工具 `qq_send_group_notice` 发送（需在「函数工具选项」里开启），群成员清单可用 `/导出 成员` 导出。

目标支持 `@`、回复消息和直接填写 QQ 号。时长参数可以放在任意位置；不带单位的数字仅在目标明确时按秒处理。

## 权限

管理指令默认允许以下身份使用：

1. AstrBot 全局管理员或插件自定义白名单
2. 群主、群管理员
3. 普通成员（仅查询类指令，默认开启）

每项能力都可以在配置中单独设置为「任何人」「群管理员」或「AstrBot 管理员」。

## 配置要点

插件只对「群组定义」里配置的群生效：同一群组内的群共享黑名单，并按群组配置禁言时长、黑名单与进群审核。单个群也可以单独建一个群组；「管理会话」可以留空，此时通知与管理都在群内完成。

- **群组定义**：填写群号列表；插件只对这些群生效。同一群组共享黑名单，管理会话留空即可（此时通知回退到申请所在群）。**同时接入多个 QQ 时**，群号对两条连接都生效（群号在 QQ 里全局唯一）；如果只想让其中一个 QQ 执行管理，把该项写成该群的会话 UMO，例如 `aiocqhttp:GroupMessage:123456`（在目标群发 `/sid` 获取），这样只有那个实例的消息会被管理。
- **管理会话**：群管理员专用会话，填写在目标会话发送 `/sid` 得到的 UMO。进群审核通知默认发到这里，里面的指令与群内完全一致——需要作用到某个群时用 `#群号` 指明（只对应一个群时可省略）。留空时通知回退到申请所在群，管理仍在各群内完成。
- **多 QQ（多个平台实例）**：通知的目标会话、`flag` 令牌、全群禁言的定时解除都带着平台实例信息，会回到产生它的那条连接上执行；所以两个 QQ 可以各管各的群，也可以共用一个管理会话（通知由收到申请的那个 QQ 发出，处理动作也走同一个 QQ）。
- **默认禁言时长**：每个群组单独配置，未填写时长时使用，默认 `10m`。
- **黑名单**：每个群组可单独启用或关闭，并设置默认拉黑原因。拉黑是**永久**的，需要时用 `/解除拉黑` 移出（旧数据里的临时条目仍会按原期限过期）。
- **拉黑后踢出**：`none` 不踢出（默认）、`current` 只把目标移出执行拉黑的这个群、`all` 移出该群组里的所有群；选项为 `all` 时，跨平台的群会走各自绑定的实例执行，失败会逐个说明。黑名单撤回默认关闭；开启后会撤回黑名单成员发送的消息，但无法阻止其他插件或模型处理该消息。
- **进群审核**：每个群组配置一套通用规则与跨群免审核，可设置启用开关、关键词、黑名单拒绝、最低 QQ 等级和未命中规则时的「默认行为」。默认行为为「保持待审」时不会主动打扰任何人：申请安静地进入待办队列，只有「进群审核通知」选了去向（默认管理会话）才会发出人工审核消息。审核只对已加入群组的群生效。
- **通知与回执**：分两类，因为触发方式不同。
  1. **指令回执**（`禁言`、`踢人`、`撤回`、`黑名单`、`导出`）永远在执行指令的会话答复；勾选某项后**额外**再发一份到该群组的管理会话（指令本来就在管理会话里执行时不会重复发）。各项含义：

| 选项 | 包含的消息 |
| --- | --- |
| `禁言` | `/禁言`、`/解禁`、`/禁言 全体` 的成功与失败回执（全群禁言的定时解除提示也走这里） |
| `踢人` | `/踢` 的成功与失败回执 |
| `撤回` | `/撤回` 的成功与失败回执 |
| `黑名单` | `/拉黑`、`/解除拉黑` 的回执，以及拉黑后自动踢出的结果；黑名单成员发言被撤回时只记日志，不发消息 |
| `导出` | `/导出 成员` / `/导出 黑名单` 的回执（成功、仅生成本地文件、失败） |

  2. **进群审核通知**由申请人触发，没有「执行会话」，所以单独选去向：`origin`（只发申请所在的群）、`manage`（只发管理会话，未配置时改发申请所在群，默认）、`both`（两者都发）、`none`（不发送，申请安静进入待办队列）。新申请、自动放行/自动拒绝、保持待审的提示，以及引用通知处理申请后的结果都跟随这里的选择。

LLM 工具（`qq_ban_member`、`qq_send_group_notice` 等）的结果只回给模型，不产生上面的任何通知。

在管理会话发送「黑名单 通知设置 [群号或群组名]」可随时查看某个群组当前的路由。

- **按群关键词**：关键词列表里直接写就是全群组通用；写成 `群号:关键词`（如 `123456:答案`）只对该群生效，两种写法可以混用。
- **跨群免审核**：直接填写来源群号（多个用逗号分隔）对所有群生效；写成 `目标群号:来源群号,来源群号` 只对指定目标群生效。申请加入目标群时，如果申请人已是来源群中任意一个的成员就直接通过，不再检查等级与关键词（黑名单仍然优先拒绝）。
- **LLM 工具**：默认全部关闭。开启前请确认对话用户可信，并建议在 WebUI「扩展 → 组件」中将工具设为 admin 级。

## 注意事项

- 插件只对「群组定义」里配置的群和管理会话生效。
- 未纳入配置的群不会响应任何指令，消息会交给其他插件或模型处理。
- 指令需要在命令和参数之间保留空格，例如 `/禁言 @用户`。
- 群公告和 QQ 等级依赖协议端扩展；不支持时会提示或跳过对应校验。
- 全群禁言的定时解除由插件维护，并会在重启后恢复。
- 管理操作需要协议端具备对应权限。

## 数据文件

数据保存在 `data/plugin_data/astrbot_plugin_qq_admin/`，更新或重装插件不会丢失：

- `blacklist.json`：黑名单
- `audit.jsonl`：审计日志
- `pending_reviews.json`：待处理进群申请
- `whole_ban.json`：全群禁言定时记录
- `exports/`：导出的临时表格
